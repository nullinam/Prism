Privacy, in plain language

How PRISM handles files.

The browser trial is designed to process supported inputs on your device. This page describes what that means and the network activity involved in visiting the site.

PRISM browser trial · Privacy and network note · Updated October 19, 2026

Your files stay on this device.

PRISM processes selected file contents locally in your browser and does not upload those contents to PRISM servers. The website host may receive standard connection data when you visit.

What happens to a selected file

  • You choose a file through your browser. PRISM reads it in the page using browser file APIs and runs the tool locally.
  • PRISM has no file-upload API route or server-side file-processing service. Its small Vercel Functions accept optional activity metadata, explicit feedback, and protected report requests only.
  • Previews and outputs are created in the browser. You choose when to save or download a result; the original file is left unchanged.
  • File names, paths, sizes, contents, tool inputs, and outputs are not sent in PRISM activity or feedback submissions. The hosting provider may still process ordinary request information.

Limits and local browser storage

Each tool shows its file and batch limits before file selection. For example, the browser trial caps image inputs at 20 MiB per file and 40 megapixels per decoded image; PDF, document, and batch tools have their own smaller limits. PDF compression, known-password unlocking, AES-256 protection, and JPEG image extraction use a locally bundled QPDF WebAssembly engine in a browser worker. Password tools do not save passwords in task recovery. PDF image extraction exports directly embedded JPEG image objects only.

Theme and appearance preferences, recent tool names, favorites, saved presets, and feedback drafts are saved in this browser’s local storage. Recent history and favorites store tool names only, never selected file names or paths. A saved preset may contain the text and options you entered for that tool; avoid saving secrets or sensitive personal information. Remove presets in the tool page or clear this site’s browser storage. When task recovery is enabled on a tool page, selected files and settings are saved in this browser’s IndexedDB so they can be restored after reload. This local copy can use significant device storage; disable recovery or clear the recovered task on the tool page, or clear this site’s browser storage. Password-generation and PDF-password tools keep recovery disabled. Trial run counters for some tools are kept in session storage and reset when the browser session ends. These values are not sent to PRISM servers by the app.

Feedback and external services

Optional activity sharing is off by default. If enabled in Settings, it sends the tool ID/name, platform, app version, and action to a PRISM Vercel Function. Feedback is sent only after you select a 1–5 rating and press Submit; the note is optional and limited to 500 characters. Skip sends nothing. A submitted feedback record contains the tool ID/name, platform, app version, rating, and optional note. Avoid passwords, contact details, filenames, file contents, and personal information. PRISM screens obvious promotional spam and rate-limits requests. When configured, accepted records are stored in Upstash Redis with caps of 2,000 activity events and 500 feedback submissions. The report page requires a private server-side admin token. The function uses a keyed hash of request IP data for rate limiting; the app does not add raw IP addresses to stored records. Vercel and Upstash may process request/hosting data under their own terms. Feedback drafts remain in this browser until submitted or cleared. If storage is unconfigured or unavailable, the form reports that feedback was not submitted. The browser trial does not collect payment details.

Network activity

When you visit PRISM, your browser requests the page and its application code, styles, and other static assets from Vercel. Vercel may process connection and request information needed to deliver, secure, and operate the site, such as IP address, requested URL, browser information, and request time. This is separate from the contents of a selected file. When a user enables activity sharing or submits feedback, the app sends only the fields described above to PRISM's Vercel Functions. Those functions contact Upstash Redis only when the storage integration is configured and reachable.

PRISM's source does not include a third-party analytics SDK, ad tracker, third-party script, or externally hosted font. First-party activity reporting is optional and disabled by default. PRISM is currently available on the web. A Windows application is planned, but no Windows or other platform app is available to download. Any future app release requires a separate review of its storage, updates, signing, and network behavior. If analytics, crash reporting, payments, or another provider is added, this notice must be updated before release.

See Vercel’s Privacy Notice and Vercel Analytics privacy details.

Review scope

PRISM has not completed runtime network verification for every tool, recovery path, and save flow on the exact release build. This privacy page describes how the released browser experience is intended to handle files and what the site transmits; it is not a 150-tool privacy certification.

Verify the promise

You can inspect the browser’s Network panel while using a file tool. Requests needed to load PRISM should go to the website host. For a local file workflow, check that the file action does not send the selected file or its contents in a request. The site also sets a Content Security Policy that restricts connections and scripts to the PRISM origin.

This is a product behavior statement, not a security certification. Browser extensions, malware, or other software on your device are outside PRISM’s control. Avoid selecting a file if your device or browser is not trusted.

Planned Windows app

PRISM is currently available on the web, and a Windows application is planned for future work. Distribution details will be published when they are confirmed. macOS, Android, iOS, and Linux apps are not currently offered. Before any app is released, its platform-specific storage, updates, signing, and network behavior must be reviewed and documented.
