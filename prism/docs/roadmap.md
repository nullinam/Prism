# PRISM roadmap

This roadmap describes planned work, not a promise that every item is already available. Tool readiness is shown in the app; browser workflows can still have format, size, or feature limits.

## Current focus

- Improve the common choose → configure → preview → process → save flow and make supported formats, trial caps, output names, progress, and recovery clear before work starts.
- Expand tool-by-tool QA with representative, large, malformed, and multi-file inputs. Keep known limitations beside the affected tool.
- Improve keyboard, screen-reader, contrast, mobile, and reduced-motion behavior across the marketing site and workspace.
- Reduce peak memory and make cancellation safe for longer local jobs.

## Planned product work

- Make task-oriented search, category navigation, favorites, and recent tools consistent across all entry points.
- Improve reusable presets and batch controls while keeping saved preferences local and explaining what each preset contains.
- Make results easier to revisit and save, with clear filenames and output summaries.
- Keep privacy claims verifiable and review network behavior when dependencies, analytics, payments, or external integrations change.
- Publish release notes and known limitations with each web release; link genuine signed desktop/mobile builds only after they are ready.

## How priorities change

PRISM is built from user feedback and tool QA. Report a specific workflow, expected result, observed result, browser/OS, and tool ID in [GitHub Issues](https://github.com/nullinam/Prism/issues). Do not include private files, passwords, or personal data in a report.
