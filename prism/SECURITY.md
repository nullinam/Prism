# Security policy

PRISM accepts responsible reports about vulnerabilities in the browser trial, desktop shell, build configuration, or dependencies.

## Report

Use the repository's private vulnerability reporting feature if GitHub enables it for this repository. Otherwise contact the maintainers through the repository owner profile and ask for a private channel before sharing exploit details. Do not publish an unpatched vulnerability in a public issue.

Include affected URL/version or commit, browser/OS, impact, and reproducible steps. Use test data only. Do not access, modify, or retain another person's data.

## Response and scope

The maintainers will acknowledge reports when practical, assess impact, and coordinate a fix and disclosure. No response-time SLA or security certification is promised. The current website is a static browser application and is not a guarantee that every tool or dependency is free of vulnerabilities. Keep dependencies updated and review generated outputs before use.

## Privacy

Do not attach real personal files, passwords, tokens, or secrets. The browser tools are intended to process supported inputs locally, but a vulnerability report should describe the issue without exposing private content.
